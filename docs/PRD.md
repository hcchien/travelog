## 1. 產品概述

### 1.1 一句話描述

Travelog 是一個陪伴旅程「行前 → 行中 → 行後」完整生命週期的旅行工具：行前與旅伴一起規劃，行中隨時查資料，行後把心得整理成遊記。

### 1.2 要解決的問題

| 階段 | 現況痛點                                                                           |
| ---- | ---------------------------------------------------------------------------------- |
| 行前 | 資料散落在 Google Doc、試算表、Google Maps 清單、LINE 群組；旅伴各自蒐集，難以合併 |
| 行中 | 訂房確認信、機票、車票 QR code 要翻 Email；網路不穩時找不到資料；時區換算容易出錯  |
| 行後 | 心得沒寫就忘了；遊記和原本的行程是兩份分開的東西                                   |

### 1.3 產品目標

1. 一個「行程（Trip）」就是所有資料的中心：計畫、訂位、文件、地點、心得都掛在同一個行程底下。
2. 多人協作：用 Passkey、Google 或 Apple 帳號登入，邀請朋友一起編輯。
3. 行中可離線查看關鍵資訊。
4. 行後可以依著行程時間軸寫心得，整理成可分享的遊記。
5. 多入口：Web、行動 App、MCP（讓 Claude 等 AI 助理直接讀寫行程）。
6. 常去的城市不用每次重找：個人地點庫跨行程保存常去的餐廳、景點，規劃時直接選入。
7. AI 一律透過 MCP：使用者在自己的 Claude 等 AI 用戶端裡規劃與調整行程，Travelog 本身不內建 AI。透過 AI 的修改都記在活動紀錄，可以一鍵復原。

### 1.4 非目標（至少在 v1 不做）

- 不做訂房/訂票的交易功能（只記錄，不代訂）。
- 不做公開社群（追蹤、動態牆、按讚排行）。遊記可公開分享連結，但不做探索頁。
- 不做完整記帳/分帳 App，只做輕量的花費紀錄（P2）。
- 不做 App 內建 AI（以 MCP 取代，見 3.4.2）。
- 不做照片上傳與相簿（含照片自動歸檔），列入未來規劃（見 3.9）。心得只支援文字。

## 2. 目標使用者與情境

### 2.1 人物誌

- **規劃者（Owner）**：主動排行程的人，會花時間研究景點、排順序、整理訂位資訊。
- **旅伴（Editor）**：會丟想去的地方、補充資料，但不一定排行程。
- **跟團者（Viewer）**：只想知道幾點在哪集合、住哪裡，行中查資料為主。
- **AI 助理使用者**：透過 Claude（MCP）說「幫我把京都第二天的行程排一下」或「我們明天住哪？」。

### 2.2 核心使用情境（User Stories）

**行前**

- 身為規劃者，我想建立一個行程，設定日期與目的地，系統自動產生每一天的空白日程。
- 身為規劃者，我想用 Google Maps 搜尋地點，加到「想去清單」，再拖拉到某一天的時間軸。
- 身為旅伴，我想透過邀請連結加入行程，並新增我想去的地方。
- 身為規劃者，我想記錄機票、住宿、交通的訂位資訊，並上傳 PDF/截圖。
- 身為常去東京的人，我想有一份「我的東京」地點庫，放每次都會去的餐廳、咖啡廳、店家，新行程直接從裡面選入，不用每次重新搜尋。
- 身為規劃者，我想在 Claude 裡請 AI 依想去清單和我的地點庫幫我排好一天，或說「第二天太趕了」讓它調整；它直接寫進 Travelog，我不滿意可以一鍵復原。
- 身為規劃者，已經訂好、買好的機票、車票、住宿和餐廳，我希望它們被釘選在時間軸上，旅伴或 AI 助理都不會不小心改到時間或拖走。
- 身為規劃者，我想在地圖上看到某一天所有點的位置與移動路線。
- 身為規劃者，我想有一份行前準備清單（打包、簽證、換匯），可指派給旅伴。

**行中**

- 身為旅伴，我打開 App 就看到「今天」的行程與下一個行程點。
- 身為旅伴，我在沒有網路的情況下也能看到今天的行程、住宿地址與訂位憑證。
- 身為旅伴，我能快速搜尋行程中的任何資料（例如「飯店」、「JR Pass」）。
- 身為旅伴，我能隨手記一則短筆記，自動附上時間與地點。
- 身為規劃者，我能臨時調整行程，其他人即時看到更新。

**行後**

- 身為旅伴，我能為整趟旅程、每一天或每個地點寫心得。
- 身為旅伴，我在行中記下的短筆記，行後可以展開成完整心得。
- 身為規劃者，我能把整趟旅程整理成一篇遊記，產生公開分享連結（可選擇隱藏住宿與訂位資訊）。
- 身為使用者，我能匯出行程（PDF / Markdown / .ics 行事曆）。

#### 3.4.1 我的地點庫（個人、跨行程）

| ID  | 功能         | 優先級 | 說明                                                                                                           |
| --- | ------------ | ------ | -------------------------------------------------------------------------------------------------------------- |
| L-1 | 收藏地點     | P0     | 從地點搜尋、行程點、想去清單一鍵「存到我的地點」；以 Google place_id 去重                                      |
| L-2 | 依城市整理   | P0     | 依地點地址自動歸到城市（如東京、京都），可手動調整；城市清單顯示地點數                                         |
| L-3 | 分類與標籤   | P0     | 預設分類：餐廳、咖啡、景點、購物、住宿；可加自訂標籤（如「必去」「雨天備案」）                                 |
| L-4 | 個人備註     | P0     | 例如必點餐點、要提早訂位、公休日提醒；只有自己看得到                                                           |
| L-5 | 規劃時選入   | P0     | 行程規劃頁右側可在「想去清單」與「我的地點（依行程目的地城市自動篩選）」之間切換，直接拖進某一天或加入想去清單 |
| L-6 | 去過紀錄     | P1     | 自動統計「去過 N 次、上次日期」（依已結束行程中的行程點計算）                                                  |
| L-7 | 行後整理     | P1     | 行程結束後提示：「這趟去了 5 個不在你地點庫的地方，要收藏嗎？」                                                |
| L-8 | 分享地點清單 | P2     | 把某個城市的地點清單分享給朋友（唯讀連結），或複製到朋友的地點庫                                               |

- 地點庫屬於個人，不屬於任何行程；加入行程時是「複製一份參考」到行程，之後修改行程點不會影響地點庫。
- 個人備註不會隨地點加入行程而被旅伴看到，除非使用者選擇一併帶入。

#### 3.4.2 AI（透過 MCP，不內建）

App 內不內建 AI 助理（2026-11-22 決議）。AI 規劃與調整一律透過 MCP（§3.7），由使用者自己的 Claude 等 AI 用戶端完成，Travelog 不負擔模型費用。日後若需要（例如讓不使用 AI 用戶端的旅伴也能用），再評估加回，工具定義已放在共用套件中可沿用。

#### 3.4.3 確定（釘選）行程點規則

| 項目      | 規則                                                                                                                   |
| --------- | ---------------------------------------------------------------------------------------------------------------------- |
| 觸發      | 行程點底下的訂位狀態改為「已訂位／已購票／已訂房」時自動釘選；或由擁有者、編輯者手動「設為確定」                       |
| 鎖定欄位  | 日期（所屬的天）、開始/結束時間、時區、地點、類型、在當天的順序；航班與車票的出發/抵達資訊                             |
| 禁止操作  | 拖拉排序、移到其他天、修改上述欄位、刪除行程點                                                                         |
| 仍可編輯  | 備註、附件（例如補上 QR code）、訂位代號等訂位明細                                                                     |
| 解除      | 擁有者或編輯者按「解除確定」，需二次確認並選擇原因（改期、取消、其他），記入活動紀錄；訂位狀態改為「已取消」時也會解除 |
| AI（MCP） | 可讀取確定狀態；修改或移動已確定行程點會被拒絕，並回傳原因；不能解除確定                                               |
| 衝突提示  | 其他行程點的時間若與已確定行程點重疊，顯示警告（不阻擋）                                                               |
| 顯示      | 圖釘圖示 + 淺橘色底，標示「已購票／已訂房／已訂位」；不顯示拖拉把手；在今日檢視中同樣標示                              |

| M-4 | 權限            | P1     | 授權時選擇唯讀或可寫入；遵守成員角色；所有寫入記入活動紀錄並標示「透過 MCP」；不能修改已確定的行程點、不能確定／解除確定、不能邀請或刪除 |
| M-5 | 復原            | P1     | 活動紀錄中透過 MCP 的修改（新增／修改／移動行程點、加入想去清單）可由編輯者以上一鍵復原；若之後已被其他人改過則無法復原                  |

使用情境範例：

- 「幫我看一下京都行第三天的行程，有沒有哪兩個點距離太遠？」
- 「把這篇文章提到的五家咖啡廳加到東京行的想去清單。」
- 「根據我第二天的行程跟筆記，幫我寫一段心得草稿。」

## 6. 成功指標

- 每趟行程的平均成員數 ≥ 2（代表協作有被使用）
- 行程期間（出發日～結束日）每日活躍比例
- 行後 14 天內有寫心得的行程比例
- MCP 工具呼叫次數 / 每週活躍 MCP 使用者
- 透過 MCP 的修改被復原的比例（越低代表 AI 寫入越可靠）
- 新行程中來自「我的地點庫」的行程點比例
